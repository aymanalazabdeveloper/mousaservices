# منظومة خدمة المواطنين

واجهة عربية RTL باستخدام HTML وCSS وVanilla JavaScript وNode.js/Express، مع تخزين الطلبات والحسابات في ملفات JSON.

## الوظائف الحالية
- تقديم طلب جديد برقم تلقائي بالشكل `REQ-YYYY-000001`.
- عرض الطلبات في لوحة الإدارة.
- تحديث حالة الطلب مع تسجيل الملاحظة والوقت واسم حساب الموظف المسجل دخوله.
- عرض سجل تحديثات الحالة للمواطن من صفحة متابعة الطلب.
- حسابات منفصلة للمدير والموظفين محفوظة في `data/users.json`.
- إنشاء أول حساب مدير مرة واحدة من `/setup.html`.
- إدارة حسابات الموظفين وتفعيلها أو إيقافها من `/users.html` (للمدير فقط).
- تخزين كلمات المرور باستخدام `scrypt` مع salt؛ لا تُحفظ كلمات المرور كنص واضح.

## التشغيل محليًا
```bash
npm install
npm start
```
افتح `http://localhost:3000/setup.html` لإنشاء أول حساب مدير. بعد ذلك سجّل الدخول من `/admin.html`، ثم استخدم رابط **إدارة الحسابات** لإضافة حسابات الموظفين.

## إعداد Railway
لا تحتاج إلى متغير `ADMIN_PASSWORD` بعد هذا التحديث. بعد النشر افتح `/setup.html` لإنشاء أول حساب مدير، ثم ادخل إلى `/admin.html`.

## تنبيهات مهمة
- ملف الحسابات هو `data/users.json`، والطلبات في `data/requests.json`.
- لا تضع ملف `users.json` في مجلد `public`؛ يجب أن يظل خارج الملفات المتاحة للتحميل العام.
- على الاستضافات التي تستخدم قرصًا مؤقتًا، قد تضيع ملفات JSON بعد إعادة النشر أو إعادة التشغيل. للحفاظ على الحسابات والطلبات على Railway، يلزم إعداد Volume دائم وربطه بمجلد `data` أو الانتقال إلى تخزين دائم.
- جلسات الدخول الحالية محفوظة في ذاكرة الخادم؛ بعد إعادة تشغيل الخدمة سيحتاج المستخدمون إلى تسجيل الدخول مجددًا.
- لم تتم إضافة رفع المرفقات في هذه المرحلة.

## إشعارات الطلبات الجديدة

- سجّل الموظف دخوله إلى `/admin.html` واضغط **تفعيل الإشعارات** على كل جهاز. لا يطلب الموقع الإذن إلا بعد الضغط. يمكن إرسال إشعار تجريبي من اللوحة.
- تعمل الميزة في سياق آمن عبر HTTPS (ويُسمح بـ localhost للتطوير)، ويجب أن يدعم المتصفح Web Push والإشعارات. الإشعار لا يتضمن بيانات المواطن، والضغط عليه يفتح لوحة الإدارة.
- على iPhone وiPad يلزم iOS/iPadOS 16.4 أو أحدث، إضافة الموقع إلى الشاشة الرئيسية، ثم فتح تطبيق الويب المثبت والسماح بالإشعارات. يدعم Safari على macOS Web Push أيضًا. [متطلبات Apple](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)
- احفظ أزواج VAPID بأمان. لتوليدها محليًا من مجلد `mousaservices`:

  ```bash
  npx web-push generate-vapid-keys
  ```

  انسخ المفتاحين اللذين يعرضهما الأمر مباشرة إلى إعدادات Railway، ولا تضعهما في Git أو في ملفات الواجهة. أضف المتغيرات التالية من Railway: **Service → Variables**:

  ```text
  VAPID_PUBLIC_KEY=<المفتاح العام الناتج>
  VAPID_PRIVATE_KEY=<المفتاح الخاص الناتج>
  VAPID_SUBJECT=mailto:admin@example.com
  ```

  استبدل البريد بعنوان تواصل تملكه. لا تطبع المفتاح الخاص في سجلات النشر. بعد حفظ المتغيرات أعد نشر الخدمة. عند غيابها تظل الخدمة والطلبات تعمل، لكن لوحة الإدارة توضّح أن الإشعارات غير مهيأة.
- تعتمد الاشتراكات على `data/push-subscriptions.json` مثل تخزين التطبيق الحالي. ملفات JSON المحلية لا تضمن البقاء على Railway بعد إعادة النشر. في Railway أنشئ Volume دائمًا للخدمة واربطه بمجلد `data` الفعلي بجانب `server.js` (إن كان جذر الخدمة مضبوطًا إلى `mousaservices` فعادةً يكون مسار الربط `/app/data`). إذا كان مجلد التطبيق يُنشر في مسار آخر، استخدم مسار `data` المطلق لذلك النشر. انقل `users.json` و`requests.json` ومجلد `uploads` الحاليين إلى الـ Volume قبل أول تشغيل عليه؛ لا تترك الملفات الأصلية التي تحتاجها خلف نقطة الربط لأن محتوى الـ Volume سيحجبها. احتفظ بنسخة احتياطية قبل النقل. هذا يحافظ على بيانات التطبيق الحالية والاشتراكات عبر النشر.
- الاشتراك مرتبط بمعرّف الموظف والجهاز، ويُحدّث عند إعادة التسجيل، ويزال عند إيقافه أو إذا أكد مزود الدفع انتهاء صلاحيته (404/410). تسجيل endpoint يتطلب جلسة موظف مسجلة، كما تقبل الخدمة عناوين مزودي Push المعروفين فقط.

### التحقق اليدوي

```bash
npm install
npm start
```

بعد ضبط مفاتيح VAPID افتح `/admin.html` على جهازين، وسجّل الدخول بحساب الموظف على كل جهاز وفعّل الإشعارات ثم جرّب زر **إرسال إشعار تجريبي**. أرسل طلبًا جديدًا من واجهة المواطن؛ يفترض أن يصل إشعار «طلب جديد» إلى الجهازين. تحديث حالة طلب قائم لا يرسل إشعارًا جديدًا. دون VAPID أو جهاز/متصفح فعلي لا يمكن التحقق من التسليم عبر مزود Push.
